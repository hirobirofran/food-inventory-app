# 依存パッケージの更新は、マイナー・パッチなら CI 通過でマージし、むやみに最新にしない

依存パッケージの更新（Dependabot の PR も、手動の更新も）を、どこまで確認してから入れるか、どの版を選ぶかを決めた。

1. **マイナー・パッチ更新は CI（lint・test・型チェック）が通ればマージする。** プレビューでの表示確認は、メジャー更新で、かつ実行時に動くパッケージ（next、react、googleapis、@google/genai など）のときだけ行う。開発時にしか使わないパッケージ（eslint、typescript、vitest、@types/node など）はメジャーでも CI だけで足りる。理由: マイナー・パッチは互換性が保たれる前提で問題がほぼ出ず、確認を必須にすると更新が滞る。メジャーは CI が通っても実機で動かないことがある
2. **むやみに最新にしない。** 公開から 7 日未満の版は使わない（`.github/dependabot.yml` の cooldown と同じ趣旨。公開日は `npm view <pkg> time --json` で確かめる）。脆弱性の修正は、修正版のうち最小の版にする（Dependabot のセキュリティ更新 PR がそれ）。脆弱性の対象外のパッケージは、同じファミリーでも一緒に上げない。理由: 新しい版を入れること自体が供給網攻撃の入口になる（2026 年の lint ツールの乗っ取り）。開発時にしか使わないパッケージも例外ではない
