# 依存パッケージの更新は、マイナー・パッチなら CI 通過でマージし、むやみに最新にしない

依存パッケージの更新（Dependabot の PR も、手動の更新も）を、どこまで確認してから入れるか、どの版を選ぶかを決めた。

1. **マイナー・パッチ更新は CI（lint・test・型チェック。ビルドは含まない）が通ればマージする。** 表示確認（Vercel プレビューで画面を開く）が要るのは、メジャー更新で、かつ成果物や実行時の挙動に影響するパッケージ（next、react、react-dom、googleapis、@google/genai、tailwindcss、@tailwindcss/postcss）のときだけ。CI で検出できる開発用ツール（eslint、eslint-config-next、typescript、vitest、@types/*、jsdom、tsx、@testing-library/*）はメジャーでも CI だけで足りる。区分は package.json の dependencies / devDependencies ではなく、成果物・実行時に影響するかで決める。1 本の PR にメジャーとマイナーが混ざるときはパッケージ単位で判定し、表示確認が要るメジャーが 1 つでも含まれる PR は表示確認する。理由: マイナー・パッチは互換性が保たれる前提で問題がほぼ出ず、確認を必須にすると更新が滞る。メジャーは CI が通っても実機で動かないことがあり、CI にビルドが無いので見た目の崩れは CI では分からない
2. **むやみに最新にしない。** 公開から 7 日未満の版は使わない（`.github/dependabot.yml` の cooldown と同じ趣旨。公開日は `npm view <pkg> time --json` で確かめる）。脆弱性の修正は、修正版のうち最小の版にする（Dependabot のセキュリティ更新 PR がそれ）。修正版が公開 7 日未満でも、脆弱性の修正は入れる（Dependabot の cooldown も脆弱性修正の PR には効かない）。脆弱性の対象外のパッケージは、同じファミリーでも一緒に上げない。ただし、上げないと CI やインストールが通らない組（peer 依存など）は例外で、そのときはこの ADR を見直す。理由: 新しい版を入れること自体が供給網攻撃の入口になる（出典 3 の発言。2026 年に lint ツールが乗っ取られた事件を指す）。開発時にしか使わないパッケージも例外ではない
