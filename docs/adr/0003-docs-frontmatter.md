# 人が読むために書いた文書には、audience・purpose・updated のフロントマターを付ける

人が読むために書いた文書の先頭に、フロントマター（ファイル先頭の `---` で囲んだ項目欄）を付けるかどうか、どの項目を書くか、どの文書に付けるかを決めた。

## 1. 項目は audience・purpose・updated の 3 つ

値は本文と同じ言語で書く（英語の `README.md` は英語で書く）。

### audience

- 書くこと: 想定読者（誰が読む想定か）と、前提知識（読むために必要な知識）
- 前提知識の線引き:
  - 読む人によって、持っているかどうかが分かれるものだけを書く
  - 先に読んでおくべき文書があれば、それを書く
  - 想定読者なら誰でも持っているもの（その文書の言語が読める、など）と、その文書の中で説明しているものは書かない
- 例: `このアプリを Google Cloud と Vercel で動かす人。Git とターミナルを使える。`、`コードを直す開発者。Next.js と TypeScript を使ったことがあり、docs/ARCHITECTURE.md を読んでいる。`
  - この ADR に例を載せる理由: 前提知識をどこまで書くかは、例が無いと、書く人ごとに細かさがばらばらになる
- 理由: 前提知識がわかれば、書く人は何を説明し何を省くかを決めやすくなり、読む人は自分向けの文書かを判断しやすくなる

### purpose

- 書くこと: 文書目的。なぜこの文書があるのか、読む人は何を得るのか、何を伝え何を残したいのか（WHY）を、一文で書く。内容の要約は書かない
- 例: 悪い例 `環境構築の手順です。`（内容の要約）。良い例 `コードの外（Google Cloud と Vercel の画面）にあってリポジトリからはわからない設定を残し、同じ環境を作り直せるようにするため。`
- 書く人にとっての使い方: この文書が扱う範囲の宣言になる
  - 文書を直すときは、直す内容が、ここに書いた目的範囲の外のことを書いていないかを確かめられる
  - 文章が膨らんだら、目的範囲が広いと受け止め、目的範囲の分割から見直すことで、どう文書分割すると適切かを見直せるようになる
- 読む人にとっての使い方: 自分向けの文書か、読んで何を得られるかを一文でつかめる

### updated

- 書くこと: 本文を最後に変えた日付（日本時間）。本文を変えたら書き換える。フロントマターだけを変えたときは書き換えない
- 理由: 人間にとって、わざわざ git の履歴を見なくても、文書を開いただけで情報鮮度（いつの内容か）がわかる。AI が文書更新する限り updated の更新の手間はかからない
- 書き換え忘れを自動で確かめる仕組みは、この ADR を入れた時点（2026-11-07）では作らない
  - 理由: この決まりは始めたばかりで、手で書き換えたときに忘れがどのくらい起きるかがまだわからない。自動で確かめるには、本文の変更とフロントマターだけの変更を見分ける作りが要り、別の作業になる

### 使わない項目

- `title`: 題名は本文の見出し 1 に書く。理由:
  - GitHub で文書を開いたときに題名として見えるのは見出し 1 で、フロントマターは表として出るだけ
  - 両方に書くと、同じ題名を 2 か所で直すことになる
- `description`: 内容を説明する欄。理由: このリポジトリには、description を読む仕組み（サイト生成ツールなど）が無い。文書の目的は purpose に書く

## 2. 付けるのは、人が読むために書いた文書

- 人が読むために書いた文書には付ける。新しく作るときも付ける
- `README.md` も対象にする。理由:
  - 外部の人は、まだ何も知らないときに README を読む。そんなとき数行で想定読者と目的がわかると、読む人は助かると思われる
  - 特にルートの README は長くなりがち。そこでフロントマターで目的を明記すれば書きすぎを防止できるのではないかと期待を寄せている（根拠はない、が、Issueスコープとかと同じ話）

次の文書には付けない。

- エージェント向けの文書（`CLAUDE.md`、`AGENTS.md`、`docs/agents/`、`handoff/`）。理由:
  - updated を付ける意味が無く、かえって害になる
  - 人間が読まないなら、目的を書いても活かされない
  - 人間向けでないことは、置き場所でわかる
- ADR の各ファイル。理由:
  - status などの専用のフロントマターを持つ
  - 決まったことは書き換えず、新しい ADR で置き換える
- `.github/` のテンプレート。理由: 先頭の項目欄は GitHub が読む設定欄
