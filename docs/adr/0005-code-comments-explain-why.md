# コードのコメントには、処理の言い直しを書かず、なぜその処理なのかを書く

コードのコメントに何を書くかを決めた。

## 1. 決まり

- コードのコメントには、処理の言い直し（コードがしていることをそのまま書いたもの）を書かない。なぜその処理なのかを書く
- 理由が無いなら、コメントを書かない
- 対象は、これから書く・直すコメント。今あるコメントを一括では書き直さない

## 2. 理由

- コードを読む人（リポジトリのオーナー、後から作業する Claude Code、公開リポジトリの読者）は、処理を消してよいか・変えてよいかを判断したい。それには理由が要る
- 処理の言い直しは、コードを読めば分かる。理由は、コードだけからは分からないことが多い

## 3. 例

例は、Terraform（インフラの設定をコードで管理するツール）を GitHub Actions で動かすワークフローのコメント。plan はインフラへの変更を計算すること、apply はその変更を反映すること。

悪い例。処理の言い直しで、なぜそうするのかが分からない。出どころは PR #117 のコミット 7e354a2 の `.github/workflows/terraform-apply.yml` の 138 行目:

    # apply の直前にもう一度 plan し、その要約を出してから、同じ plan をそのまま apply する

良い例。同じ箇所を書き直したものの一部で、plan の結果ファイルを apply に渡す理由を書いている。出どころは同じ PR のコミット 68dc0d6 の、同じファイルの 140 行目:

    # 結果ファイル（tfplan）を apply に渡すのは、ログに出した要約と反映する中身を一致させるため。

## 4. Claude Code とレビューへの伝え方

- CLAUDE.md（Claude Code がセッションの始めに読む指示ファイル）の「重要ルール」に、この決まりを書く。コードを書く Claude Code が、毎回のセッションで読むため
- Claude Code は、次の 3 つのレビューを頼むたびに、CLAUDE.md の「コードレビューの手順」にある「書き添える文」を依頼に添える
  - セルフレビュー: ドラフト PR を作る前に、Claude Code が別のエージェントに差分をレビューさせる。その依頼文に添える
  - `/code-review`: Claude Code のレビュー用のコマンド。コマンドの引数（`--comment` の後ろ）に添える
  - Codex: OpenAI のコーディングエージェント。PR のコメントで codex をメンションするとレビューする。そのコメントに添える
- 添えるのは、`/code-review` で差が出たため。添えずに実行した回は、コードのコメントの問題を 1 件も挙げなかった。悪い例のコメントは、そのときの差分にもあった（コミット 5087a68 の同じファイルの 126 行目）。添えた回は 9 件挙げた（出典 2・3）
- 書き添える文は、CLAUDE.md の「コードレビューの手順」の節にだけ置く。スキル（Claude Code に読み込ませる手順書）、PR テンプレート、AGENTS.md（Codex などのエージェントが読む指示ファイル）には書かない
- `docs/agents/domain.md` には「手順になったものはスキルにする」とある。この手順は、置き場を 1 か所にするため、その例外とする
- AGENTS.md に書かないのは、Codex を呼ぶ PR のコメントに書けば足りるため。また、AGENTS.md に書いても、Codex がそれに沿ってレビューしたかを、結果から見分ける方法が無いため
- `/simplify`（Claude Code の、コードの重複や無駄を見つけて直すコマンド）には添えない。コードのコメントの中身を確かめるのは役割の外で、セルフレビュー・`/code-review`・Codex の 3 つで足りる
