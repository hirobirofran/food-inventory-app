# Issue の完了条件は、直す場所ではなく「どういう状態にするか」で書く

Issue の完了条件の書き方を決めた。

## 決め

- 完了条件には、Issue が終わったときの状態を書く。
- 直す場所と直し方は、完了条件に書かない。
- ファイル名と行番号は、確かめたときの根拠として、Issue のコメントに書く。
- 完了条件を書き直すときも、同じように書く。書き直すのは、着手時の要件定義のときと、Issue を開け直したとき。

例:

- 悪い例: `src/app/layout.tsx` の `description` に「PWA」と書かれていない
- 良い例: 実態とドキュメント（コードコメント含む）が一致している

## 理由

- 直す場所を名指しすると、確かめるのはその場所だけになる。同じ種類の抜けがほかに残っていても、条件は満たされてしまう。
- 状態で書けば、その状態になっているかを全体で確かめることになる。
- Issue #19 では、完了条件が確かめるファイルを名指ししていた。名指しの外に残った抜けが、マージの後に 2 回見つかった（PR #99 の後に 1 か所、PR #101 の後に 3 か所）。
- 悪い例は、Issue #19 を開け直したときに出た案で、これも直す場所を名指ししていた。
