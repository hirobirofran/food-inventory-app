# ドキュメントとコードコメントには版数や値を書かず、実物を指す

ドキュメントとコードコメントには、版数や値を書かない。
代わりに、その値が書いてある実物（コードや設定ファイル）を指す。

1. **版数や値を書かず、実物を指す。**
   最新の値は、コードや設定ファイルにある。
   ドキュメントには、その場所を書く。
   例: パッケージの版は `package.json` を見る、と書く。版数そのものは書かない。
2. **コードコメントも対象にする。**
   オーナーは、ドキュメントのずれにコードコメントも含めた（出典 1・2）。
3. **書きたい理由があるときは、オーナーに相談する。**
   たとえば、アーキテクチャの説明のために、その版だけを含めたい場合である。
   理由があれば、書いてよいかをオーナーに相談する。
   理由が無いのに、あちこちに版数や値を書くことはしない。

## 理由

書いた値は、実物が変わるとずれる。
ずれた記載を直すには手間がかかる。
Issue #19 では、ドキュメントと実態を一致させるのに、PR #99・#101・#103 の 3 本が要った。
意味のない二重管理（同じ情報を 2 か所に持つこと）を作らないために、値を書かずに実物を指す。
