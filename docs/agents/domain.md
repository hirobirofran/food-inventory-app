# ドメイン文書の読み方

このリポジトリで作業するエージェント全般（スキルを使うときも、使わないときも）の読み方。

## 調べる前に読む

- ルートの `GLOSSARY.md`
- `docs/adr/`: まず `README.md`（索引、1 件 1 行）を見て、いま触る領域に関わる ADR だけ読む

無いものは黙って飛ばす。無いことを指摘したり、先に作ろうと提案したりしない。用語や決定が実際に固まったときに `/domain-modeling` が作る。

## ADR の運用（このリポジトリの決め）

- `status: proposed` はまだ決まっていないこと、`accepted` は決まったこと。見直したら `superseded by ADR-NNNN`、使わなくなったら `deprecated`
- 書く基準は `/domain-modeling` の ADR 形式と同じ。元に戻しにくい、文脈なしでは意外、本物のトレードオフがある、の 3 つがそろうとき
- `handoff/ideas/` との使い分け: やりたいこと（未着手の案）は ideas、決めたこと・決めかけていることは ADR
- ADR を作ったら `docs/adr/README.md` の索引に 1 行足す（最初の ADR では「（まだ無い）」の行を消す）
- 毎セッション守らせることだけ、CLAUDE.md に 1 行で参照を足す。手順になったものはスキルにする。ADR には「なぜ」を残す
- 出典（日時と発言）を付ける。書式は `/domain-modeling` の ADR 形式

## 用語は GLOSSARY のとおりに使う

Issue の題名、提案、仮説、テスト名で、GLOSSARY が避けている同義語に流れない。無い用語が要るなら、作らずに記録して `/domain-modeling` に回す。

## ADR と食い違うとき

黙って上書きせず、「ADR-0007 と矛盾するが、見直す価値があるのは…」と明示する。
